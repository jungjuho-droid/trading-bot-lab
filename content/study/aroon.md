## 질문의 각도가 다르다

대부분의 지표는 가격의 크기를 잰다. RSI는 오른 폭과 내린 폭의 비율을, 볼린저는 평균에서 떨어진 거리를, 이동평균은 평균 자체를 본다. 전부 **얼마나**를 묻는다.

아룬은 다르다. 이건 **언제**를 묻는다. 정확히는 "최근 n봉 중에서 최고가를 찍은 게 몇 봉 전인가"를 센다. 가격이 얼마나 올랐는지는 전혀 보지 않는다. 이 각도가 이 지표를 특별하게 만든다.

이름은 산스크리트어로 새벽빛을 뜻하는 단어에서 왔다고 한다. 추세가 시작되는 순간을 잡겠다는 뜻이겠다.

<div class="term">
<div class="term-bar"><i></i><i></i><i></i><em>아룬 — 공식</em></div>
<pre><code><span class="c">기본 기간 n = 25 (원저자 권장), 실무에선 14~25 를 많이 쓴다</span>
<span class="w">Aroon Up   = (n − 최고가 이후 경과 봉수) / n × 100</span>
<span class="w">Aroon Down = (n − 최저가 이후 경과 봉수) / n × 100</span>
<span class="y">Aroon Oscillator = Up − Down        범위 −100 ~ +100</span>
<span class="c">읽는 법</span>
<span class="g">  Up = 100    바로 이 봉이 n봉 신고가  →  방금 고점을 갱신했다</span>
<span class="g">  Up = 0      n봉 전이 최고가          →  그 뒤로 한 번도 못 넘었다</span>
<span class="w">  오실레이터 > 0   고점 갱신이 저점 갱신보다 최근 → 상승 우세</span>
<span class="w">  오실레이터 < 0   그 반대 → 하락 우세</span>
<span class="r">주의: 가격이 얼마나 올랐는지는 계산에 안 들어간다. 오직 시점만 본다</span></code></pre>
</div>

## 시간만 보면 무엇이 좋은가

가격 크기를 무시하는 게 왜 장점이 될 수 있을까. 한 가지 성질 때문이다. **크기 기반 지표는 이상치에 흔들리는데, 시간 기반 지표는 안 흔들린다.**

<div class="term">
<div class="term-bar"><i></i><i></i><i></i><em>급등 한 방이 들어왔을 때</em></div>
<pre><code><span class="c">시나리오: 조용하던 종목에 1봉짜리 +30% 스파이크</span>
<span class="r">RSI       평균 상승폭이 폭발 → 순식간에 과매수 구간, 며칠간 왜곡 지속</span>
<span class="r">볼린저    표준편차 급증 → 밴드가 벌어져 이후 신호가 다 무뎌짐</span>
<span class="r">이동평균  평균이 들려 올라감 → n봉 동안 영향</span>
<span class="g">아룬      "최고가가 방금이다" → Up = 100. 그게 전부.</span>
<span class="g">          +30% 든 +3% 든 값이 같다</span>
<span class="y">장점: 이상치에 강건하다 (robust)</span>
<span class="y">단점: 강한 움직임과 약한 움직임을 구분 못 한다 — 바로 이 지표의 최대 약점</span></code></pre>
</div>

장점과 단점이 같은 뿌리에서 나온다는 게 흥미롭다. 크기를 안 보니까 이상치에 안 흔들리고, 크기를 안 보니까 강도를 모른다. 그래서 아룬은 단독으로 쓰기보다 **크기 기반 지표와 짝지을 때** 의미가 생긴다. 서로 못 보는 것이 정확히 반대이기 때문이다.

## 박스권 감지라는 진짜 특기

아룬이 다른 지표보다 확실히 잘하는 게 하나 있다. 옆으로 기는 장을 알아채는 것이다.

<div class="term">
<div class="term-bar"><i></i><i></i><i></i><em>박스권에서 아룬의 모양</em></div>
<pre><code><span class="c">추세장 (상승)</span>
<span class="g">  Up   ▔▔▔▔▔▔▔▔  90~100 근처에 붙어 있음 (계속 신고가)</span>
<span class="r">  Down ▁▁▁▁▁▁▁▁  0 근처</span>
<span class="w">  오실레이터 +80 ~ +100 유지</span>
<span class="c">박스권</span>
<span class="y">  Up   ╱╲╱╲╱╲╱╲  중간대에서 진동</span>
<span class="y">  Down ╲╱╲╱╲╱╲╱  역시 중간대</span>
<span class="w">  오실레이터 0 근처에서 왔다 갔다 — 둘 다 낮으면 '아무 일도 안 일어나는 중'</span>
<span class="g">유용한 조합 판정</span>
<span class="g">  Up < 50 AND Down < 50   →  최근 절반 구간에 고점도 저점도 갱신 없음</span>
<span class="g">                               = 명확한 정체 구간</span>
<span class="c">이 판정은 오실레이터(차이) 만 봐서는 안 나온다 — Up·Down 을 각각 봐야 한다</span></code></pre>
</div>

마지막 줄이 실무 포인트다. 오실레이터는 Up과 Down의 차이라서 정보가 한 겹 줄어든다. Up 20 / Down 20도 0이고 Up 60 / Down 60도 0인데, 앞은 완전 정체이고 뒤는 양쪽 다 활발한 상태다. 봇에 넣을 거라면 오실레이터 하나만 받지 말고 세 값을 다 들고 있어야 한다.

## 코드

<div class="term">
<div class="term-bar"><i></i><i></i><i></i><em>python — 함정은 창 길이와 동점 처리</em></div>
<pre><code><span class="g">def aroon(high, low, n=25):</span>
<span class="g">    <span class="c"># 최근 n+1 봉 안에서 최고/최저가 몇 봉 전인지</span></span>
<span class="g">    up   = high.rolling(n+1).apply(lambda x: x.argmax(), raw=True) / n * 100</span>
<span class="g">    down = low.rolling(n+1).apply(lambda x: x.argmin(), raw=True) / n * 100</span>
<span class="g">    return up, down, up - down</span>
<span class="r"># 함정 1: 창 길이가 n 이 아니라 n+1 이다</span>
<span class="r">#         '현재 봉 포함 n봉 전까지' 를 보려면 n+1 개가 필요하다. 여기서 1 틀리면</span>
<span class="r">#         Up 이 100 에 절대 안 닿거나 항상 닿는 이상한 지표가 된다</span>
<span class="r"># 함정 2: 동점. 같은 고가가 두 번 나오면 argmax 는 앞의 것을 고른다</span>
<span class="r">#         최근 것을 기준으로 하려면 뒤에서부터 찾아야 한다 (플랫폼마다 관행이 다름)</span>
<span class="r"># 함정 3: 고가/저가를 쓴다 — 종가 기준이 아니다. 꼬리가 값에 그대로 반영된다</span></code></pre>
</div>

함정 3은 은근히 크다. 고가·저가 기준이라 긴 꼬리 한 번에 Up이 100으로 튄다. 종가 기준으로 바꾸면 지표 성격이 꽤 달라지는데, 어느 쪽이 맞다기보다 **무엇을 신고가로 칠 것인가**의 정의 문제다. 봇에서는 이 정의를 명시해두지 않으면 나중에 백테스트와 실전이 갈린다.

## ADX와 뭐가 다른가

추세의 존재를 판정하는 지표로 훨씬 유명한 게 ADX다. 둘을 비교하면 아룬의 자리가 분명해진다.

<div class="term">
<div class="term-bar"><i></i><i></i><i></i><em>아룬 vs ADX</em></div>
<pre><code><span class="w">ADX (평균방향성지수)</span>
<span class="c">  재료: +DI / −DI — 가격이 위아래로 움직인 '크기' 를 누적</span>
<span class="c">  출력: 0~100. 추세의 강도만 나타내고 방향은 안 나타냄</span>
<span class="c">  성질: 와일더 평활이 두 번 들어가 매우 느리다</span>
<span class="w">아룬</span>
<span class="c">  재료: 극값이 나온 '시점'</span>
<span class="c">  출력: Up/Down 각각 0~100, 오실레이터는 −100~+100 (방향 포함)</span>
<span class="c">  성질: 평활이 없다. 극값이 갱신되는 순간 즉시 튄다</span>
<span class="y">핵심 차이</span>
<span class="g">  ADX  는 크기를 누적 평활 → 늦지만 안정적</span>
<span class="g">  아룬 은 시점을 그대로 → 빠르지만 계단식으로 튄다</span>
<span class="r">아룬의 값은 연속적이지 않다. n=25 면 값이 4 단위로만 움직인다 (100/25)</span>
<span class="c">  이 계단 성질 때문에 임계값 비교가 생각보다 거칠다 — 미세 조정이 안 먹힌다</span></code></pre>
</div>

마지막 줄이 실무에서 중요하다. 아룬은 n으로 나눈 값이라 **이산적**이다. n=25면 0, 4, 8, 12… 이렇게만 나온다. 임계를 50으로 잡든 52로 잡든 결과가 같을 수 있다는 뜻이다.

이건 파라미터 스윕을 할 때 알아둬야 하는 성질이다. 후보값을 촘촘하게 늘어놓아 봐야 실제로는 몇 개의 구간으로 뭉친다. RSI처럼 연속적인 지표와 같은 방식으로 스윕하면 계산만 낭비한다. 지표마다 값의 알갱이 크기가 다르다는 걸 알고 설계해야 한다.

## 기간을 얼마로 둘 것인가

원저자 권장은 25다. 이 숫자가 어디서 왔는지 따져볼 필요가 있다.

<div class="term">
<div class="term-bar"><i></i><i></i><i></i><em>n 을 바꾸면</em></div>
<pre><code><span class="w">n 작음 (10~14)</span>
<span class="g">  최근 구간만 본다 → 반응이 빠르다 · 값의 알갱이가 굵다 (100/14 ≈ 7.1)</span>
<span class="r">  잦은 극값 갱신으로 100 과 0 을 자주 오간다</span>
<span class="w">n 큼 (25~50)</span>
<span class="g">  값이 부드럽다 · 알갱이가 곱다 (100/50 = 2)</span>
<span class="r">  오래전 극값에 계속 묶여 최근 변화를 늦게 반영</span>
<span class="y">15분봉 기준 환산</span>
<span class="y">  n=14  →  3.5시간 창</span>
<span class="y">  n=25  →  6.25시간 창</span>
<span class="y">  n=96  →  정확히 24시간 창</span>
<span class="c">마지막 줄이 흥미롭다 — n=96 이면 내 봇의 저점근접 게이트와 같은 창이 된다</span>
<span class="g">즉 '24시간 저점 대비 거리(크기)' 와 '24시간 저점 갱신 이후 경과(시간)' 를</span>
<span class="g">같은 창에서 비교할 수 있다. 대조 실험을 짜기에 딱 좋은 조건이다</span></code></pre>
</div>

n=96 아이디어는 이 글을 쓰면서 나온 것이다. 기간을 원저자 권장값이 아니라 **내 시스템의 다른 부품과 창 길이를 맞춰서** 정하면, 두 지표를 공정하게 비교할 수 있다. 같은 데이터 창을 크기로 재느냐 시간으로 재느냐만 다른 상태가 되니까.

## 내 봇과 붙여보면

아룬과 내 전략의 궁합을 따져보면 정직하게 애매하다.

<div class="term">
<div class="term-bar"><i></i><i></i><i></i><em>궁합 점검</em></div>
<pre><code><span class="w">내 전략: 과매도 눌림목 반등 — 빠진 것을 사되 돌기 시작한 것을 산다</span>
<span class="r">✗ 아룬 오실레이터가 크게 음수 = 저점을 계속 갱신 중</span>
<span class="r">   눌림목처럼 보이지만 실제로는 '떨어지는 칼' 일 확률이 높다</span>
<span class="r">   현행 게이트가 이미 저점근접·낙폭 상한으로 이 구간을 다룬다 — 중복 우려</span>
<span class="g">✓ Aroon Down 이 최근 급락 후 회복 = 저점 갱신이 멈춘 시점</span>
<span class="g">   '돌기 시작했다' 의 시간 기반 정의가 될 수 있다</span>
<span class="g">   현행 반등 확인은 저점 대비 반등률(%) — 크기 기반이다</span>
<span class="y">   → 두 정의가 같은 것을 다르게 재고 있다. 어느 쪽이 나은지는 측정할 문제</span>
<span class="w">✓ 박스권 판정 (Up·Down 둘 다 낮음) 을 레짐 보조 축으로</span>
<span class="c">   현행 레짐 판정은 BTC 4시간봉 방향 하나만 본다 — 방향은 보지만 정체는 못 본다</span></code></pre>
</div>

두 번째 항목이 제일 해볼 만하다. 지금 내 봇은 반등을 "저점 대비 몇 % 올라왔나"로 판정한다. 아룬식으로 하면 "저점 갱신이 멈춘 지 몇 봉 됐나"가 된다. 같은 현상의 다른 측정이다.

이 비교가 의미 있는 이유는 앞에서 말한 강건성 때문이다. 크기 기반 반등 확인은 한 봉짜리 큰 양봉에 쉽게 걸린다. 시간 기반이라면 그런 봉 하나로는 조건이 안 채워진다. 휩쏘를 줄이는 방향일 가능성이 있고, 반대로 진입이 늦어져 이익 앞부분을 버릴 가능성도 있다. 어느 쪽인지는 재봐야 안다.

<div class="term">
<div class="term-bar"><i></i><i></i><i></i><em>검증 설계</em></div>
<pre><code><span class="w">가설: "저점 갱신 정지(시간 기반)가 반등률(크기 기반)보다 나은 진입 확인이다"</span>
<span class="g">  ① 기간 n ∈ {14, 20, 25}</span>
<span class="g">  ② 조건 A: 현행 반등률 게이트 (대조군)</span>
<span class="g">  ③ 조건 B: Aroon Down 이 특정 값 아래로 내려간 뒤 k봉 경과</span>
<span class="g">  ④ 조건 C: A AND B (둘 다)</span>
<span class="y">목적함수는 셋을 함께 본다 — 평균수익 · 승률 · 손절권 진입률</span>
<span class="y">하나만 좋아지고 다른 게 나빠지면 채택하지 않는다</span>
<span class="r">이 표에 결과 숫자가 없는 건, 아직 안 돌려봤기 때문이다.</span>
<span class="c">C(둘 다)가 이길 것 같지만, 조건을 겹칠수록 진입 빈도가 급감한다는</span>
<span class="c">전례가 있어서 낙관하지 않는다 — 표본이 마르면 검증 자체가 불가능해진다</span></code></pre>
</div>

마지막 우려는 경험에서 나온 것이다. 예전에 거래량 조건을 하나 더 얹으려다 후보가 46건에서 6건으로 줄어든 적이 있다. 단독으로는 성적이 좋았던 조건인데, 다른 게이트들이 이미 비슷한 걸 걸러내고 있어서 겹쳐 놓으니 통행량만 죽었다. 조건을 더하는 일은 항상 이 위험을 안고 간다.

## 이 지표가 잘 안 쓰이는 이유

아룬은 1995년에 나왔는데 RSI나 MACD만큼 퍼지지 않았다. 이유를 생각해보면 몇 가지 짚인다.

<div class="term">
<div class="term-bar"><i></i><i></i><i></i><em>보급이 안 된 이유들</em></div>
<pre><code><span class="r">① 그림이 안 예쁘다</span>
<span class="c">   계단식으로 튀어서 부드러운 곡선이 안 나온다</span>
<span class="c">   지표의 확산에는 시각적 설득력이 꽤 크게 작용한다</span>

지표가 유명해지는 것과 유용한 것 사이에 큰 상관이 없다는 건, 이 코너를 하면서 계속 확인하는 사실이다. 유명한 지표는 대개 설명이 짧고 그림이 예쁘다. 그 두 조건은 유용함과 별 관계가 없다.

거꾸로 말하면, 덜 알려진 지표를 볼 때는 "왜 안 퍼졌나"를 먼저 물어보는 게 좋다. 성능이 나빠서 안 퍼진 것과, 설명하기 어려워서 안 퍼진 것은 완전히 다른 얘기니까.

## 조합해서 쓴다면

아룬을 단독으로 쓰지 않는다는 전제에서, 어떤 지표와 짝지으면 좋을지 정리해둔다. 기준은 하나 — **못 보는 것이 반대인 지표**를 고르는 것이다.

크기를 재는 지표와의 조합이 우선이다. 아룬이 "최근에 저점을 갱신했다"고 알려주면, RSI나 낙폭 지표가 "얼마나 깊게 빠졌나"를 채워준다. 시점과 크기가 둘 다 있어야 판단이 된다.

거래량과의 조합도 말이 된다. 아룬은 가격의 극값만 보므로 그 극값이 거래를 동반했는지 모른다. 거래가 거의 없는 상태에서 찍힌 저점은 의미가 약한데, 아룬은 그걸 구분하지 못한다.

반대로 **스토캐스틱이나 CCI와 묶는 건 별로다.** 셋 다 결국 최근 구간에서의 상대 위치를 보는 것이라 정보가 크게 겹친다. 지표를 셋 켜놓고 다 같은 방향을 가리킨다고 확신이 커지는 건 착각일 수 있다. 같은 재료를 세 번 본 것뿐이니까.

## 마무리

아룬은 유명한 지표가 아니다. RSI나 MACD처럼 어디서나 보이지도 않는다. 그런데 이 코너에서 다룰 가치가 있다고 생각한 건, 질문의 각도가 다르기 때문이다.

지표를 여러 개 쓴다고 정보가 그만큼 늘지는 않는다. RSI와 스토캐스틱과 CCI를 동시에 켜봐야 셋 다 "얼마나 올랐나"를 조금씩 다르게 볼 뿐이다. 정말로 정보를 늘리려면 **다른 종류의 질문**을 하는 지표를 섞어야 한다. 크기를 재는 것 하나, 시간을 재는 것 하나, 거래량을 보는 것 하나, 호가를 보는 것 하나.

그런 의미에서 아룬은 좋은 지표라기보다 좋은 축이다. 내 게이트 목록에 시간 기반 축이 아직 하나도 없다는 걸, 이 글을 쓰면서 알았다.
