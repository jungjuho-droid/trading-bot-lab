## 처음 배운 규칙, 제일 먼저 버린 규칙

먼저 밝혀둔다. 이 글은 새 지표를 소개하는 글이 아니다. 써보고 접은 물건의 부검 보고서다. 그래서 다른 편들과 결이 좀 다르고, 쓰는 나도 별로 유쾌하지 않다.

차트를 처음 열면 누구나 만나는 게 이동평균선이다. 처음 배우는 매매 규칙도 대개 이것이다. 짧은 이동평균이 긴 이동평균을 아래에서 위로 뚫으면 사고(골든크로스), 반대면 판다(데드크로스).

내 봇도 여기서 시작했다. 빗썸에서 업비트로 옮긴 직후를 나는 MA봇 시절이라고 부르는데, 진입 판단이 통째로 이동평균 교차였기 때문이다. 지금 봇에는 그 규칙이 한 줄도 안 남아 있다.

## 평균의 종류부터

이동평균은 하나가 아니다. 실무에서 부딪히는 건 대개 세 가지다.

<div class="term">
<div class="term-bar"><i></i><i></i><i></i><em>같은 이름, 다른 계산</em></div>
<pre><code><span class="w">SMA  단순이동평균   최근 n봉을 똑같은 무게로 평균</span>
<span class="c">     close.rolling(n).mean()</span>
<span class="c">     성질: n봉 전 값이 빠질 때 튄다 (드롭오프 효과)</span>
<span class="w">EMA  지수이동평균   최근 값에 더 큰 무게, 과거는 지수적으로 감쇠</span>
<span class="c">     close.ewm(span=n, adjust=False).mean()</span>
<span class="c">     성질: 반응이 빠르다. 대신 노이즈도 빨리 받는다</span>
<span class="w">RMA  와일더 평활   EMA 의 일종이지만 alpha = 1/n (더 무겁다)</span>
<span class="c">     close.ewm(alpha=1/n, adjust=False).mean()</span>
<span class="c">     성질: RSI·ATR 내부에서 쓰는 그 평균. EMA(n) 보다 느리다</span>
<span class="r">주의: EMA(14) 와 RMA(14) 는 다른 값이다. alpha 가 2/15 대 1/14 로 다르다</span>
<span class="y">교차 전략에서 SMA→EMA 로 바꾸면 신호 시점이 통째로 이동한다.</span>
<span class="y">즉 '어떤 평균이냐' 는 파라미터가 아니라 전략의 일부다</span></code></pre>
</div>

이걸 먼저 정리하는 이유. 백테스트 결과를 비교할 때 기간(20/60)만 적고 종류(SMA/EMA)는 안 적는 글이 정말 많다. 같은 20/60 교차라도 SMA와 EMA는 전혀 다른 매매를 한다.

## 이동평균이 실제로 하는 일

교차로 넘어가기 전에 평균 자체를 한 번 보자. 이동평균은 흔히 "추세선"이라 불리는데, 신호처리 쪽 언어로 옮기면 저역 통과 필터다. 빠른 진동을 걷어내고 느린 흐름만 남기는 장치.

<div class="term">
<div class="term-bar"><i></i><i></i><i></i><em>평균이 걸러내는 것과 남기는 것</em></div>
<pre><code><span class="c">원본 가격 = 느린 흐름 + 빠른 진동(노이즈)</span>
<span class="g">이동평균 통과 후 = 느린 흐름만 (거의)</span>
<span class="w">기간 n 이 커질수록</span>
<span class="g">  더 많은 진동을 제거한다 → 선이 매끈해진다</span>
<span class="r">  동시에 더 느려진다 → 실제 변화를 늦게 반영한다</span>
<span class="y">이건 트레이드오프가 아니라 물리적 제약이다</span>
<span class="y">  노이즈를 지우려면 정보를 평균 내야 하고, 평균을 내려면 시간이 필요하다</span>
<span class="r">"부드러우면서 빠른 이동평균" 같은 건 존재하지 않는다</span>
<span class="c">HMA·ZLEMA 같은 변형들이 이 제약을 우회하려 시도하지만,</span>
<span class="c">대개 과거를 외삽하는 방식이라 반전 구간에서 오버슈팅한다</span></code></pre>
</div>

마지막 항목을 굳이 적은 이유가 있다. "지연 없는 이동평균"을 내세우는 지표를 종종 보기 때문이다. 대부분 과거 값의 기울기로 앞을 조금 내다보는 방식인데, 방향이 바뀌는 순간 그 외삽이 정확히 반대로 작동한다. 공짜는 여기서도 없다.

## 진짜 문제는 지연이다

이동평균은 정의상 과거의 평균이다. 그러니 현재 가격보다 늦다. 얼마나 늦는지 대충 말고 수치로 보면 이렇다.

<div class="term">
<div class="term-bar"><i></i><i></i><i></i><em>지연의 크기</em></div>
<pre><code><span class="c">SMA(n) 의 무게중심은 n봉의 한가운데 → 이론적 지연 ≈ (n−1)/2 봉</span>
<span class="w">  SMA(20)  ≈  9.5봉 지연</span>
<span class="w">  SMA(60)  ≈  29.5봉 지연</span>
<span class="c">15분봉 기준으로 환산하면</span>
<span class="y">  SMA(20)  ≈  2시간 22분 전의 평균을 보고 있는 셈</span>
<span class="y">  SMA(60)  ≈  7시간 22분 전</span>
<span class="r">교차는 두 지연선이 만나는 시점이다 — 사건이 아니라 사건의 그림자</span>
<span class="c">EMA 는 이보다 빠르지만 (span n 의 지연 ≈ (n−1)/2 를 넘지는 않음)</span>
<span class="c">빨라진 만큼 가짜 교차도 늘어난다. 공짜는 없다</span></code></pre>
</div>

여기서 골든크로스의 정체가 드러난다. 이건 "지금부터 오른다"는 신호가 아니라 "이미 한동안 올랐다"는 사후 확인이다. 상승이 시작되고, 짧은 평균이 따라 올라오고, 그게 긴 평균을 넘을 때까지 걸리는 시간만큼 가격은 이미 가 있다.

추세가 길게 이어지는 시장이라면 그래도 괜찮다. 남은 구간이 있으니까. 내가 보던 시간축은 그런 시장이 아니었다.

## 휩쏘, 교차 전략의 사망 원인

가격이 옆으로 기면 두 평균선이 서로 얽힌다. 그러면 교차가 연달아 터진다.

<div class="term">
<div class="term-bar"><i></i><i></i><i></i><em>횡보장에서 벌어지는 일</em></div>
<pre><code><span class="w">가격 ──╲─╱─╲──╱╲──╱─╲──╱   (방향 없이 진동)</span>
<span class="g">단기  ───╲╱───╲╱───╲╱───     긴 평균 근처에서 계속 교차</span>
<span class="c">장기  ─────────────────</span>
<span class="r">  ↑골든  ↓데드  ↑골든  ↓데드  ↑골든  …</span>
<span class="r">  매수  손절   매수  손절   매수</span>
<span class="w">비용 계산 (업비트 기준, 왕복 수수료 0.1% 가정)</span>
<span class="r">  휩쏘 10회 = 수수료만 1.0% + 스프레드·호가 관통 별도</span>
<span class="r">  저가 코인은 호가 한 칸이 0.2% 를 넘기도 한다 — 실측 사례 있음</span>
<span class="g">즉 방향이 맞아도 자주 틀리면 수수료가 먼저 계좌를 비운다</span></code></pre>
</div>

호가 한 칸 이야기는 직접 겪었다. 본전 보호선을 +0.2%에 뒀는데 27건을 실측해 보니 평균 실현이 +0.017%였고 합계로는 마이너스였다. 원인은 슬리피지가 아니었다. 호가 관통이다. 443원짜리 코인에서 호가 한 칸이 0.226%였으니, 0.2%짜리 선은 호가와 호가 사이 허공에 떠 있었던 것이다. 관통 손실에 왕복 수수료를 얹으면 손익분기가 0.283%. 그래서 바닥을 0.4%로 올렸다.

이 계산은 교차 전략에도 그대로 얹힌다. 교차 한 번 뜰 때마다 왕복 0.1%가 나가고 호가가 넓은 종목이면 거기에 0.2%가 더 붙는데, 그게 하루에 몇 번씩 반복되면 방향을 맞히든 틀리든 계좌는 같은 속도로 얇아진다. 하루에 몇 번씩 교차가 뜨는 종목에서 이걸 돌리면 방향 예측이 얼마나 정확하든 진다.

## 골든크로스는 정말 통계적으로 유효한가

여기에 확답할 자신은 없다. 내 매매기록으로 교차 전략을 제대로 스윕해본 적이 없어서다. 어떻게 확인해야 하는지 정도는 말할 수 있다.

<div class="term">
<div class="term-bar"><i></i><i></i><i></i><em>교차의 유효성을 재는 절차</em></div>
<pre><code><span class="w">가설: "골든크로스 이후 k봉 동안의 수익률이 무작위 시점보다 높다"</span>
<span class="g">  ① 실험군  교차 발생 시점 이후 k봉 수익률을 전부 수집</span>
<span class="g">  ② 대조군  같은 기간에서 무작위로 뽑은 시점의 k봉 수익률</span>
<span class="g">  ③ 비교    실험군 평균이 대조군 분포의 바깥에 있는가</span>
<span class="y">k 를 여러 값으로 (4, 16, 96봉 = 1시간·4시간·24시간) 각각 측정</span>
<span class="c">추가로 봐야 할 것</span>
<span class="c">  · 교차 직후 되돌림의 크기 (손절에 걸릴 확률)</span>
<span class="c">  · 신호 빈도 (비용 계산의 분모)</span>
<span class="r">주의: 상승장 구간만 뽑아 재면 무엇을 해도 이긴다</span>
<span class="r">      상승·하락·횡보 구간을 각각 나눠서 봐야 한다</span></code></pre>
</div>

마지막 주의사항이 교차 백테스트에서 특히 중요하다. 코인 시장에는 큰 상승 구간이 몇 번 있었고, 그 구간을 끼워서 재면 추세추종 전략은 대개 좋아 보인다. 그 구간이 아닐 때가 진짜인데, 실전에서는 그런 시기가 훨씬 길다.

내가 이걸 안 재본 이유는 솔직히 우선순위에서 밀려서다. 전략은 이미 눌림목으로 갈아탔고, 표본은 한정돼 있고, 재봐야 할 후보는 줄을 서 있다. 버린 전략을 검증하느라 표본을 쓰느니 지금 쓰는 게이트를 다듬는 쪽이 급했다.

그래도 언젠가는 재보고 싶다. "교차를 버린 게 옳았나"를 숫자로 확인하고 싶어서. 지금은 "박스장에서 돌파가 대부분 가짜였다"는 관찰 하나로 버린 상태다. 그건 인상이지 측정이 아니다.

## 선을 여러 개 깔면 나아지나

휩쏘에 데인 사람들이 흔히 시도하는 게 이동평균을 여러 개 까는 것이다. 5, 10, 20, 60, 120을 한꺼번에 그려놓고 순서가 가지런한지 보는 방식. 정배열이니 역배열이니 하는 말이 여기서 나온다.

<div class="term">
<div class="term-bar"><i></i><i></i><i></i><em>여러 선을 쓰는 방식과 그 정체</em></div>
<pre><code><span class="w">정배열   5 > 10 > 20 > 60 > 120   (짧은 게 위)</span>
<span class="w">역배열   5 < 10 < 20 < 60 < 120   (긴 게 위)</span>
<span class="c">판정: 순서가 가지런한 봉 수를 세거나, 선들 사이 간격의 합을 본다</span>
<span class="g">좋아지는 점</span>
<span class="g">  교차 하나가 아니라 다섯 선의 합의를 요구 → 휩쏘가 확실히 줄어든다</span>
<span class="r">나빠지는 점</span>
<span class="r">  다섯 선이 다 정렬되려면 시간이 더 걸린다 → 지연이 더 커진다</span>
<span class="r">  교차 1회의 지연이 SMA(60) 기준 30봉이라면, 정배열 완성은 그보다 늦다</span>
<span class="y">즉 휩쏘와 지연을 맞바꾼 것이지 문제를 푼 게 아니다</span>
<span class="c">이 교환이 이득인지는 그 시장의 추세 지속 길이에 달렸다 — 다시 측정 문제로 돌아온다</span></code></pre>
</div>

여기서 하고 싶은 말은 "조건을 더 붙이면 좋아진다"는 직관이 자주 틀린다는 것이다. 조건을 더하면 오탐은 줄지만 미탐이 늘고, 무엇보다 신호 빈도가 줄어 표본이 마른다. 표본이 마르면 그 조건이 좋은지 확인할 방법도 같이 사라진다.

이걸 정면으로 맞은 적이 있다. 단독으로는 성적이 좋던 거래량 조건을 다른 게이트들 위에 얹었더니 후보가 46건에서 6건으로 줄었다. 87%가 사라졌다. 필터가 하나 늘어난 게 아니었다. 검문소만 세워서 길을 막은 것이었다.

## 승률이 낮아도 되는 전략, 그렇지 않은 전략

교차 전략을 옹호하는 흔한 논리가 있다. 승률은 낮아도 이길 때 크게 이기니 괜찮다는 것. 추세추종의 표준 서사다.

논리 자체는 건전하다. 다만 그게 성립하려면 조건이 붙는다.

<div class="term">
<div class="term-bar"><i></i><i></i><i></i><em>낮은 승률이 감당되는 조건</em></div>
<pre><code><span class="w">기대값 = 승률 × 평균이익 − 패률 × 평균손실 − 비용</span>
<span class="c">승률 30% 로 흑자를 내려면</span>
<span class="c">  평균이익 / 평균손실 비율이 최소 2.34 이상이어야 한다 (비용 제외)</span>
<span class="c">  비용까지 넣으면 3 이상은 필요하다</span>
<span class="w">그 비율이 나오려면</span>
<span class="g">  · 이익 분포에 긴 꼬리가 실제로 존재해야 한다</span>
<span class="g">  · 그 꼬리를 끝까지 탈 수 있어야 한다 (오래 보유 가능)</span>
<span class="g">  · 손실은 짧게 자를 수 있어야 한다 (슬리피지 작아야)</span>
<span class="r">내 봇의 실측은 이 조건과 거리가 있었다</span>
<span class="c">  눌림목 진입 18건 재현 — 최대 평가이익 중앙값 +3.09%</span>
<span class="c">  이익 구간 체류시간 중앙값 0분</span>
<span class="r">  긴 꼬리가 없고, 있어도 탈 시간이 없다</span></code></pre>
</div>

여기서 중요한 건 추세추종이 나쁘다는 얘기가 아니다. 내 시장과 내 시간축에서 그 전제가 안 맞았다는 것이다. 일봉으로 몇 주씩 들고 가는 전략이면 완전히 다른 얘기가 된다.

같은 판단이 손절 설계에서도 나왔다. 실제 매매 58건을 손절선별로 재현했더니, 손절이 아예 없을 때 기대값이 −0.072%였고 −2.5%로 자르면 +0.209%로 뒤집혔다. 반대로 익절에 상한을 씌우자 기대값이 도로 음수가 됐다. 손실은 자르고 이익은 풀어주라는 오래된 격언을 내 계좌 숫자가 그대로 재현한 것이다.

그런데 같은 데이터가 다른 것도 말해줬다. 익절 수준을 어떻게 골라도 결과의 중앙값이 −2.100%에서 안 움직였다는 것. 이익 쪽을 아무리 정성껏 설계해도 손실 11건(61%)이 결과를 쥐고 있었다. 이익을 키우는 것보다 손실을 줄이는 쪽이 훨씬 큰 지렛대였다.

교차 전략의 문제도 결국 여기로 모인다. 휩쏘가 만드는 잦고 작은 손실이 전체를 갉아먹는데, 그 손실은 방향 예측을 잘한다고 줄지 않는다. 신호 빈도 자체가 만드는 구조적 비용이라서 그렇다.

## 그럼 왜 아직도 쓰이나

그런데도 이동평균은 여전히 거의 모든 차트에 깔려 있다. 이유가 있다.

첫째, 추세 필터로는 훌륭하다. 진입 신호로 안 쓰고 "지금 이 종목이 장기 평균 위인가 아래인가"만 보면 느린 게 오히려 장점이 된다. 느리다는 건 잘 안 바뀐다는 뜻이고, 잘 안 바뀌는 기준선은 필터로 쓸 만하다.

둘째, 모두가 본다. 60일선, 120일선 같은 숫자는 실제로 많은 사람이 주문을 걸어두는 자리다. 피보나치 편에서 다룬 자기실현 구조와 같은 논리다. 근거가 약해도 참여자가 많으면 실재가 된다.

<div class="term-bar"><i></i><i></i><i></i><em>내 봇에서 이동평균의 최후</em></div>

마지막 줄이 웃긴 대목이다. 중기추세 게이트를 처음 넣을 때 값을 -12%로 뒀다가 나중에 -30%로 크게 풀었는데, 그 커밋 제목이 "게이트가 전략과 반대로 작동"이었다. 눌림목은 빠진 걸 사는 전략인데, 고점 대비 -12% 이내만 통과시키는 게이트는 안 빠진 종목만 들여보내고 있었다. 게이트 하나하나는 그럴듯한데 전략과 방향이 어긋나 있었다.

이동평균 교차도 같은 종류였다. 교차는 "오르기 시작한 걸 따라 타는" 논리고, 눌림목은 "빠진 걸 미리 줍는" 논리다. 두 문법은 한 봇 안에서 같이 살기 어렵다.

## 그래도 살릴 자리

버렸다고 쓸모가 없다는 얘기는 아니다. 지금 봇에 이동평균을 다시 넣는다면 후보는 세 곳이다.

마지막 줄이 핵심이다. 게이트가 이미 열 개 서 있는 시스템에 열한 번째를 얹을 때 던져야 할 질문은 "이게 좋은 지표인가"에서 멈추면 안 된다. "나머지 열 개가 못 보는 걸 이게 보는가"까지 가야 한다. 이격도는 낙폭 게이트와 재는 대상이 거의 겹쳐서 새 정보를 못 줄 공산이 크다. 그러면 통과 후보만 깎고 성과는 그대로인 검문소가 하나 더 생긴다.

## MA봇 시절에 실제로 있었던 일

그 시절을 좀 더 구체적으로 적어두는 게 나을 것 같다. 이동평균 교차로 봇을 돌린다는 게 실제로 어떤 모습이었는지.

<div class="term">

교차 로직 자체는 이후 몇 번 형태를 바꾸다 사라졌다. 처음엔 교차 하나로 샀고, 다음엔 교차에 다른 조건을 붙였고, 돌파 전략기에는 트리거 자리를 고점 돌파에 내줬고, 눌림목 전환에서 아예 지워졌다.

## 지표보다 먼저 겪은 건 통신 문제였다

MA봇 시절 얘기에서 빼놓을 수 없는 게 하나 더 있다. 지표 얘기가 아니고, 데이터를 받아오는 문제였다.

종목을 몇백 개씩 스캔하기 시작하니 REST로 하나씩 조회하는 방식이 감당이 안 됐다. API 호출 제한에 걸리고, 응답이 느려지고, 어떤 종목은 데이터가 비어서 돌아왔다. 그래서 웹소켓을 붙였더니 이번엔 연결이 끊겼다.

<div class="term">
<div class="term-bar"><i></i><i></i><i></i><em>통신 안정성이 밟아온 계단</em></div>
<pre><code><span class="w">REST 폴링         종목 수가 늘자 한계</span>
<span class="w">웹소켓 도입       실시간 수신, 대신 연결 끊김 문제</span>
<span class="w">3회 재시도        끊기면 세 번까지 다시</span>

<span class="w">연결 상태 추적    끊긴 횟수·마지막 수신 시각을 상태로 관리</span>

지표 스터디에 통신 얘기를 끼워 넣는 게 이상해 보일 수 있다. 그런데 실제로 봇을 만들면 이쪽이 시간을 훨씬 많이 잡아먹는다. RSI 계산은 다섯 줄이면 끝난다. 그 계산에 넣을 캔들을 안정적으로 받아오는 일이 훨씬 어렵다.

지난 편에 "지표는 봇의 10%"라고 썼는데, 나머지 90% 중 상당 부분이 이런 것들이다. 데이터 수집, 완성봉 확정, 체결 확인, 원장 대조. 하나도 화려하지 않고 글감으로도 재미없다. 그런데 이게 안 되면 좋은 지표를 붙여봐야 소용이 없다.

직접 검증해볼 분을 위해 최소 절차를 적어둔다. 교차 전략은 백테스트가 유독 잘 속는 종류라서 그렇다.

<div class="term">
<div class="term-bar"><i></i><i></i><i></i><em>교차 백테스트에서 반드시 넣어야 할 것</em></div>
<pre><code><span class="r">① 비용을 넣는다</span>

## 기간 숫자는 어디서 왔나

20, 60, 120 같은 숫자의 출처를 아는 사람은 의외로 적다. 대부분 주식 시장의 달력에서 왔다. 한 달 거래일이 대략 20일, 분기가 60일, 반년이 120일.

코인 시장에는 그 달력이 없다. 주말도 없고 폐장도 없다. 20일선이 "한 달 평균"이라는 의미가 성립하지 않는다. 그런데도 다들 20/60/120을 쓴다.

<div class="term">
<div class="term-bar"><i></i><i></i><i></i><em>기간 숫자를 다시 정한다면</em></div>
<pre><code><span class="c">주식에서 온 숫자        코인 15분봉으로 환산</span>
<span class="w">  20일  = 한 달        20봉  = 5시간</span>
<span class="w">  60일  = 분기         60봉  = 15시간</span>
<span class="w">  120일 = 반년         120봉 = 30시간</span>
<span class="r">환산해 보면 의미가 전혀 다르다 — 같은 숫자를 쓸 이유가 없다</span>
<span class="g">코인 시장의 자연스러운 주기라면</span>
<span class="g">  96봉  = 24시간   (하루)</span>
<span class="g">  672봉 = 7일      (일주일)</span>
<span class="y">그런데도 20/60 을 쓰는 게 완전히 틀렸다고 하기도 어렵다 —</span>
<span class="y">많은 사람이 그 선을 보고 있다면, 그 선이 실제로 작동하기 때문이다</span></code></pre>
</div>

이 딜레마는 피보나치 편에서 다룬 자기실현 문제와 판박이다. 근거가 없는 기준선도 참여자가 충분하면 실재가 된다. 그래서 답은 "어느 쪽이 맞나"에서 안 나온다. "둘 다 후보로 놓고 재본다"가 답이다. 20/60과 96/672를 나란히 스윕해서 어느 쪽이 내 매매기록에서 나은지 본다. 이론으로 못 정하면 측정으로 정한다.

## 교차 대신 쓰는 것들

교차를 버린 자리에 뭐가 들어왔는지도 적어두는 게 공평하겠다. "지금 이 종목을 살 만한가"라는 같은 질문에 다른 방식으로 답하는 조건들이다.

<div class="term">
<div class="term-bar"><i></i><i></i><i></i><em>교차가 있던 자리를 채운 것들</em></div>
<pre><code><span class="c">교차가 하던 일: "방향이 바뀌었나" 를 판정</span>
<span class="w">현행에서 그 질문을 나눠 맡은 조건들</span>

이 구조의 장점은 어디가 문제인지 보인다는 데 있다. 교차 하나로 판정할 때는 신호가 안 나오면 그냥 안 나오는 것이었다. 지금은 게이트별 통과율이 찍히니 어느 관문이 병목인지 바로 잡힌다.

단점도 뚜렷하다. 파라미터가 여섯 개면 조합의 수가 폭발한다. 각각을 따로 튜닝하면 조합에서 무너지고, 조합까지 다 훑으면 계산량이 감당이 안 된다. 그래서 축별 스윕 → 상위 조합 재검증이라는 두 단계로 끊는다.

조건이 늘수록 과적합 위험이 커진다는 것도 인정해야 한다. 파라미터 여섯 개를 8.9일치 기록에 맞추면 그 기록에만 잘 맞는 값이 나오기 쉽다. 기간을 반으로 갈라 앞뒤에서 모두 성립하는지 보는 절차를 끼워 넣은 게 그래서인데, 그것도 위험을 깎을 뿐이지 없애지는 못한다.

## 한 줄 요약을 굳이 남긴다면

이동평균 교차를 쓰려는 사람에게 딱 세 가지만 확인시키고 싶다.

첫째, 내가 쓰는 게 SMA인지 EMA인지 알고 있는가. 같은 20/60이라도 다른 전략이다. 둘째, 신호 한 번당 왕복 비용이 얼마인지 계산해봤는가. 하루에 신호가 몇 번 나는지와 곱해보면 수익률 얘기를 꺼내기 전에 답이 나오는 경우가 많다. 셋째, 이 전략이 통하려면 추세가 얼마나 길게 이어져야 하는지 아는가. 지연이 30봉이면 최소한 그보다 긴 추세가 필요하다.

세 질문 다 지표에 관한 게 아니다. 내 시장과 내 비용 구조에 관한 것이다. 지표는 어디서 가져와도 되지만 이 답은 내가 직접 재야 한다. 나는 그걸 몰라서 MA봇 시절을 한 달 가까이 썼다. 그 시간이 아깝다고까지는 못 하겠는데, 다시 하고 싶지도 않다.

## 버린 전략을 기록으로 남기는 이유

블로그에 실패한 전략 이야기를 올리는 게 이상해 보일 수 있다. 보통은 잘된 것만 쓰니까.

나한테는 이쪽이 더 중요하다. 이유가 둘이다.

첫째, 같은 실수를 반복하지 않으려고. 몇 달 뒤에 이동평균 교차가 다시 좋아 보이는 순간이 올 수 있다. 그때 이 글이 있으면 "아, 이래서 버렸지"가 떠오른다. 없으면 또 시도하고 또 같은 자리에서 막힌다.

둘째, 잘된 것만 남기면 그건 기록이 아니고 광고다. 461개 버전 중 성공한 건 소수고 나머지는 전부 이런 종류의 시행착오였다. 그 비율을 감추면 봇 개발이 실제보다 쉬워 보인다. 읽는 사람에게 도움이 안 되는 그림이다.

우연은 아닐 것이다. 진입 조건은 시장 상황에 따라 유효성이 뒤집히지만, 잃지 않는 구조는 어느 장에서도 필요하다. 7주 연속 마이너스를 맞고 나서야 이 순서를 받아들였다. 잃지 않는 구조를 먼저 세우고, 버는 건 그다음.

## 마무리

이동평균 교차는 내 봇이 처음 배운 규칙이고 가장 먼저 버린 규칙이다. 버리는 과정에서 배운 게 지표 자체보다 값졌다. 신호의 지연을 봉 수로 환산해보는 습관. 왕복 비용을 신호 빈도와 곱해보는 습관. 새 조건을 넣기 전에 기존 조건과의 중복부터 의심하는 습관.

교차 전략을 깎아내릴 생각은 없다. 다만 그게 잘 통하는 시장이 따로 있다. 추세가 길고, 수수료 비중이 작고, 호가가 촘촘한 시장. 그걸 알고 쓰는 것과 모르고 쓰는 건 완전히 다른 일인데, 나는 모르고 썼고 수업료를 계좌로 냈다.

## 덧붙임, 이동평균을 쓰는 다른 방법 하나

버린 전략만 소개하고 끝내면 좀 그러니, 지금도 유효하다고 보는 쓰임 하나를 남긴다. 이격도다.

이격도는 가격이 이동평균에서 얼마나 떨어져 있는지를 백분율로 재는 값이다. 계산은 간단하다.

<div class="term">
<div class="term-bar"><i></i><i></i><i></i><em>이격도 — 교차보다 눌림목 전략에 맞는 쓰임</em></div>
<pre><code><span class="g">이격도 = (현재가 − 이동평균) / 이동평균 × 100</span>
<span class="c">  양수  평균 위에 있다</span>
<span class="c">  음수  평균 아래로 떨어져 있다</span>
<span class="w">왜 눌림목 전략과 문법이 맞나</span>
<span class="g">  교차는 '오르기 시작한 것' 을 찾는다 — 내 전략과 방향이 반대</span>
<span class="g">  이격도는 '많이 떨어진 것' 을 찾는다 — 방향이 같다</span>
<span class="y">다만 예상되는 문제: 기존 낙폭 게이트와 재는 게 거의 같다</span>
<span class="r">  낙폭 게이트  = 며칠 고점 대비 얼마나 빠졌나</span>
<span class="r">  이격도       = 평균 대비 얼마나 빠졌나</span>
<span class="c">  기준점만 다를 뿐 '얼마나 빠졌나' 라는 질문은 동일하다</span>
<span class="c">  → 상관이 높으면 중복 검문소가 된다. 검증 1순위 확인 항목</span></code></pre>
</div>

이 후보를 아직 안 넣은 이유가 마지막 항목이다. 새 조건을 넣기 전에 기존 조건과의 상관부터 봐야 하는데, 이격도는 낙폭 게이트와 상관이 높을 공산이 크다. 그러면 통과 후보만 깎이고 성과는 제자리인 결과가 나온다.

그래도 재볼 가치는 있다고 본다. 기준점이 다르다는 건 미묘하지만 실제 차이를 만든다. 고점 대비 낙폭은 한 지점을 기준으로 삼고, 이격도는 여러 봉의 평균을 기준으로 삼는다. 고점이 이상치였다면 두 값이 크게 갈린다.

이런 식으로 후보 목록에 올려두고 순서를 기다리는 아이디어가 여러 개 있다. 전부 재보면 좋겠는데 표본이 한정돼 있으니 기대 효과가 큰 것부터 가는 수밖에 없다. 이격도는 지금 그 목록 중간쯤에 있다. 상관계수만 먼저 뽑아보는 건 반나절이면 될 것 같은데, 그것도 이번 주에는 못 할 것 같다.

## 약어 풀이

\* 이 글에 나온 영어 약어를 풀어 둔다.

- **RSI** (Relative Strength Index): 상대강도지수. 일정 기간 평균 상승폭과 평균 하락폭의 비율을 0~100 으로 나타내 과매수·과매도를 재는 모멘텀 오실레이터.
- **MA** (Moving Average): 이동평균. 일정 기간 가격의 평균을 이어 그린 선. 추세의 방향과 지지·저항의 기준으로 쓴다.
- **SMA** (Simple Moving Average): 단순이동평균. 기간 안의 가격을 같은 가중치로 평균한 값.
- **EMA** (Exponential Moving Average): 지수이동평균. 최근 가격에 더 큰 가중치를 두어 SMA 보다 빠르게 반응하는 이동평균.
- **ATR** (Average True Range): 평균진폭. 고가·저가·전일 종가를 아우르는 하루 실제 변동폭(True Range)의 이동평균. 변동성 지표.
- **BTC** (Bitcoin): 비트코인. 이 블로그에서는 코인 시장 전체의 방향(레짐)을 재는 기준 자산.
- **API** (Application Programming Interface): 프로그램끼리 데이터와 기능을 주고받는 규약. 거래소 API 로 시세를 받고 주문을 낸다.
- **REST** (Representational State Transfer): HTTP 요청·응답으로 자원을 주고받는 API 설계 방식. 거래소 API 대부분이 이 형태다.
- **TP** (Take Profit): 익절. 목표 수익에서 포지션을 정리하는 것. TP1·TP2·TP3 는 분할 익절 단계.
